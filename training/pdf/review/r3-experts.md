# 3차(최종) 검토: 전문가 자문교사 3인 승인 검토

기준: SPEC.md '검증 추가'·'입장 코드'. 2차에서 지적한 섹션의 text/<id>.txt만 다시 읽음.
SPEC '입장 코드'는 사용자 요청이므로 "교사 이름이 든 앱에 입장 코드를 걸고 올리는 것" 자체는 문제로 잡지 않았습니다. 대신 보안을 부풀리지 않는지, 같은 책 안에서 말이 엇갈리지 않는지만 봤습니다.

## 공통 최종 확인

- 입장 코드(ep8 98~109행, ep12 23·112행, ep16 52행): '가림막', "코드를 몰라도 파일 안의 글자는 그대로 보입니다", 민감 정보는 코드가 있어도 올리지 않기, 공개 게시판 금지, 학기마다 변경, 정보 담당 상의, 공용 PC에서는 '다시 묻지 않기' 끄기가 모두 들어 있음. 보안을 과장하지 않음. 남은 것은 setup의 말 엇갈림과 '통과 표시'가 코드를 바꿔도 남는 문제(아래 1-1, 2-1).
- 인정점(ep9 75행, ep10 53·84행, ep11 39행): "지어낸 예시", "우리 학교 규정을 따르세요", 위원회 확정이 들어 있음. 출결 구분 용어도 고쳐짐.
- 당겨오기(ep7 9·39행·114행): "예시, 학교 방식과 다르면 고쳐 확정", "앱 기록 ≠ 공식 기록", 교체 절차·나이스 반영이 들어 있음.
- /rewind(ep15 94·109·115행): SPEC과 같음(코드만 / 코드와 대화). 명령으로 지운 파일은 안 될 수 있다는 단서와 데스크톱 앱 메뉴 차이 단서가 있음.
- Firebase(setup 111~147행): login은 직접, init은 직접 또는 설정 파일 직접 만들기, 질문·답은 "버전에 따라 다름"으로 단서를 닮. SPEC의 '미확인, 단정 금지'에 맞음.
- 플러그인(setup 82행): 설정 › 사용자 지정 › 플러그인 경로, "uv로 내 PC에서 도는 방식이라 데스크톱 앱에서만"이 SPEC과 같음. `--scope user`도 명령에 들어감(48행).

### 그대로 내보내면 안 되는 남은 문제

- [중] setup | "교사 명단이나 성적이 든 앱은" | ep8·ep16은 "입장 코드 없이는 올리지 않기"인데 setup 113행만 무조건 금지라서, 세 곳이 다시 엇갈린다 | "교사 이름이 든 앱은 입장 코드 없이 올리지 않습니다(EP 8). 학생 성적·연락처는 코드가 있어도 올리지 않습니다"로 고친다
- [중] ep8 | "기존 기기는 '이 기기에서 잊기'" | 학기마다 코드를 바꿔도, 전에 통과한 기기에는 '통과 표시'가 남아 계속 열린다. 남의 기기에서 '잊기'를 눌러 줄 수 없으니 코드를 바꿔도 접근이 막히지 않는다 | 101행 프롬프트에 "통과 표시는 코드 버전과 묶어서, 코드를 바꾸면 모든 기기에서 다시 묻게 해 줘"를 더하고, 102행의 '기존 기기는 잊기를 누릅니다'를 지운다
- [하] setup | "이 책의 설치는 모두 그렇게" | 38행은 "모든 설치를 클로드에게 시킬 수 있다"고 하는데, 122행 firebase login은 선생님이 직접 해야 한다. 서로 맞지 않는다 | "(브라우저 로그인 단계는 직접 합니다)"를 붙인다
- [하] setup | "안 보이는 것이 정상입니다" | SPEC은 "데스크톱 앱에서만 동작"이라고만 한다. 웹에서 목록에는 보이는데 동작하지 않을 수도 있다(확인 필요) | "웹 claude.ai·휴대폰 앱에서는 동작하지 않습니다"로 고친다

### 판정: 조건부 승인
조건: setup 113행 문장을 ep8·ep16과 맞추고, 입장 코드 프롬프트에 "코드를 바꾸면 모든 기기에서 다시 묻기"를 넣는다.
