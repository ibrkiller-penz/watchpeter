# 1차 검토 종합 — 수정 계획 (팀장)

검토 의견 7개(r1-beginner, r1-novice, r1-20s, r1-50s, r1-expert-tech, r1-expert-admin, r1-expert-design)를 SPEC.md(개정 3·4판, 정정 우선)에 비추어 정리했습니다. 원고는 편집자가 고치고, 그림·shell.html·CSS는 편집장이 맡습니다.

## 1차 핵심 판단
1. 가장 급한 것은 **초보가 실제로 막히는 세 곳**: (가) 로컬 폴더를 "claude.ai/code에서도 연다"는 오안내(EP 6·10·14), (나) 장마다 다른 파일 이름(규칙표.md/시간표.html/검산표.csv → 규칙표.xlsx·진짜시간표.html·정답표.csv로 통일), (다) 폴더 만들기·탐색기·확장자·터미널·허락 질문 답하기 같은 기본 조작 설명 누락(EP 0·세팅).
2. **안전·규정 지적은 전부 반영**: 되돌리기 전 "사라지는 것 먼저", 정리 전 폴더 복사 필수, 정적 사이트의 입장 비밀번호는 보안이 아님, 교사용 자료는 같은 공개 사이트에 올리지 않음, 결시 사유 구분(경조사=출석인정), 학업성적관리위원회 심의, 수업 교체는 학교 절차·나이스 반영, 실명 명단은 지침 확인 후에만.
3. **검산 신뢰성 복구**: EP 7 정답 사례를 클로드가 만들게 한 프롬프트를 "사람이 정답 열을 채운다"로 바꾸고, EP 11 대화 예시의 "소수 저장 오차" 설명은 "반올림 구현 차이"로 고침(36.75는 정확히 표현되는 값). 숫자 예시는 규칙 범위 안(74/75점 → 36.8/36.7)으로.
4. 20대 교사의 중복·지루함 지적은 **요약 상자·참조로 해결하고 초보용 설명은 지우지 않음**(한 줄 기준 반복 정리, 발표자 사례 압축, 에이전트 절 축약, 제작 과정 메타 삭제). 분량이 늘어도 됨.
5. 확인 안 된 새 사실(Fable 뜻·요금, Cowork 플러그인 메뉴 경로, /rewind, firebase init 권장 답, --scope user, gh CLI, 저작권법 제25조 요건 문구)은 본문에 단정으로 넣지 않고 **'확인 필요' 목록(편집장 → 검증자)**으로 넘김. 큰 장 순서 변경(세팅 장 뒤로, Pro·메뉴 순서)은 3차 구성팀 안건.

## 공통 규칙 (세 편집자 모두)
- 파일 이름 통일: `진짜시간표.html`, `인정점.html`, `규칙표.xlsx`, `정답표.csv`(예시 8건, "5~10건" 표현은 허용). `시간표.html`, `규칙표.md`, `검산표.csv`, "10건"이 보이면 모두 고친다.
- 로컬 폴더 작업은 "Claude 데스크톱 앱의 Code 메뉴"로만. "(또는 claude.ai/code)" 문구는 지운다. claude.ai/code는 EP 0·도구 고르기에서만 "GitHub 저장소를 쓸 때(클라우드)"로 설명.
- 되돌리기 문장은 항상 이 형태: `"마지막 저장 지점으로 되돌려 줘. 되돌리기 전에 어느 지점으로 가는지와 그 뒤에 한 작업 중 무엇이 사라지는지 먼저 알려 줘."` 그리고 본문에 한 줄: "되돌리면 그 지점 이후에 고친 내용은 사라집니다. 그래서 잘 될 때마다 저장 지점을 남깁니다."
- 용어는 "허락 질문" 하나로(확인 질문·확인 요청 → 허락 질문). 슬래시 명령은 처음 나올 때 "입력창에 /clear를 글자 그대로 치고 Enter" 식으로.
- 메뉴 경로의 시작점은 "왼쪽 아래 내 이름(계정) → 설정"으로 통일. 사용량 경로는 메뉴 지도 표기(설정 › 환경설정 › 사용량)로 맞추되 "버전에 따라 다를 수 있음"을 한 번만.
- 프롬프트에서 개발 용어는 쉬운 말 먼저, 용어는 괄호 한 번: "붙여 넣은 데이터를 인터넷으로 보내는 코드(fetch, XMLHttpRequest, 외부 주소 호출, 폼 전송)가 있는지".
- 새 사실을 추가해야 할 때 근거가 없으면 문장 끝에 `(확인 필요)`를 붙여 두고 편집장 목록에 알린다. 추측으로 버튼 이름·단축키를 만들지 않는다.

## 반영 안 함 (이유 한 줄)
- [beginner setup] Cowork 플러그인 설치 경로를 "설정 › 사용자 지정 › 플러그인"으로 단정 — 확인 안 된 메뉴 이름(확인 필요로만, A-19).

- [expert-tech setup] `Set-ExecutionPolicy … RemoteSigned` 명령 게재 — 학교 PC 보안 정책 우회로 읽힐 수 있어 싣지 않음(novice 의견 채택, A-24).
- [expert-tech ep15] "/rewind·Esc 두 번 체크포인트" 본문 추가 — SPEC '단축키 지어내지 말 것', 검증 후 2차에.
- [expert-tech ep12] `firebase hosting:channel:deploy` 명령 본문 게재 — 확인 후. 지금은 "임시 미리보기 기능은 확인 필요".
- [20s pro] 에이전트·교차 검증 절 삭제 수준 축소 — 발표자 6차 요청(교차 검증·토큰 관리) 사항이라 절은 유지, 길이만 절반(A-8).
- [beginner colophon] 제작 과정 전면 삭제 — SPEC이 "카톡 캡처 한 장 + 세 줄 요청, 팀을 짜서"를 사실로 두므로 압축만(E-5).

## 3차 구성팀 검토 안건
1. 시작 전 4장(도구·Pro·메뉴·세팅)의 순서와 위치: 세팅 장을 부록 앞으로 옮기고 각 EP '준비'에서 참조하게 할지, 순서를 도구 → 메뉴 → Pro → 세팅으로 바꿀지.
2. Pro 장의 에이전트·교차 검증 절을 부록 '고급'으로 옮길지.
3. EP 7(약 40분, 6단계)을 두 EP로 나눌지, 아니면 B-12의 '멈춤 지점' 상자로 충분한지.
4. 세팅 체크리스트 표의 위치(장 앞 vs 뒤 vs 양쪽, A-16 임시 조치) 확정.
5. 각 장 산출 파일 이름을 모은 한 표(진짜시간표.html·인정점.html·규칙표.xlsx·정답표.csv·정답사례.csv)를 어디에 둘지(부록 '한 장 요약' 또는 차례 옆).
6. 발표자 사례 상자의 분량 기준(3~4문장)과 디자인(접는 상자 등).
7. colophon을 남길지, 남기면 분량·위치(판권면 수준으로 축소).
8. hook 라벨 "이런 일이 됩니다"의 디자인 처리(CSS 가상 요소 vs 마크업).
