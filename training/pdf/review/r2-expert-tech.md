## 새 문제

- [상] ep8 | "교사 이름이 든 앱을 올린다면" | 같은 장 '이럴 땐'의 "교사 실명이 든 시간표는 올리지 마세요", 3단계 "공개 사이트에 올리면 안 됩니다", 세팅 5절 "교사 명단이나 성적이 든 앱은 올리지 마세요"와 정면으로 어긋나 독자가 어느 쪽을 따를지 모릅니다. 또 정적 HTML에 이름을 넣어 올리면 이름은 파일 안에 글자 그대로 있어서, 코드를 '풀' 필요도 없이 소스 보기만으로 보입니다. "파일 안을 들여다보면 풀 수 있어"는 실제 노출보다 가볍게 들립니다 | 앞의 세 문장을 "입장 코드 없이는 올리지 마세요"로 맞춥니다. 가림막 상자에는 "코드를 몰라도 파일 안의 이름은 그대로 보입니다"를 씁니다. 입장 코드 프롬프트에는 "코드와 시간표 데이터를 파일에 그대로 적지 말고, 맞는 코드를 넣어야 데이터가 풀리게 해 줘(코드는 8자 이상)"를 넣습니다. 구현이 되는지와 효과는 확인이 필요합니다. 이 앱은 원래 데이터 없이 붙여 넣는 구조이므로, 이름을 넣어 둔 판일 때만 해당한다고도 밝힙니다
- [중] ep8 | "그 기기에서는 다시 묻지 않게" | 이 기능은 브라우저 저장(localStorage)을 써야 하는데, 같은 장의 "localStorage 같은 곳에는 몰래 저장하지 마"와 충돌합니다. 바로 뒤 '외부 전송·저장 점검'에서도 문제로 잡힙니다. 교실·교무실 공용 PC에서 한 번 넣으면 다음 사람도 그대로 열 수 있습니다 | 프롬프트에 "통과했다는 표시만 저장하고, 코드나 데이터는 저장하지 마. '이 기기에서 잊기' 버튼을 만들어 줘"를 넣습니다. 본문에는 "공용 PC에서는 기억하기를 쓰지 않습니다"를 넣습니다. 점검 프롬프트에도 "입장 표시 저장은 예외"라고 적습니다
- [중] ep8·ep12 | "(확인 필요: firebase use)" | 편집용 표시와 "(절차는 세팅 장 5절 기준)"이 붙여 넣을 프롬프트 안에 들어가 있습니다. 클로드는 책의 '세팅 장'을 모릅니다. ep8에서는 "먼저 올리지 말고 점검만"이라고 해 놓고, 새로 넣은 줄이 "index.html 이름으로 복사해서 올려 줘"라고 해서 확인 전에 배포할 수 있습니다. ep12는 여러 파일로 된 사이트인데 한 파일용 "index.html 이름으로 복사"를 그대로 옮겨 와, 파일 하나만 올라가거나 링크가 깨질 수 있습니다 | 프롬프트에서 편집 표시와 책 장 참조를 빼고 "내 Firebase 프로젝트가 이 폴더에 연결돼 있는지 확인해 줘"로 씁니다. ep8은 "public 폴더에 index.html 이름으로 복사만 해 두고 아직 올리지 마"로 바꿉니다. ep12는 "사이트 폴더 전체(첫 화면 index.html, 차시 페이지·css·사진·pdf)를 public에 넣어 줘"로 바꿉니다
- [중] ep12 | "실제 휴대폰 확인은 올린 뒤" | '확인하기'가 '저작권 점검 후 공유하기'보다 앞에 있어, 따라 하면 저작권·개인정보 점검 전에 공개 주소로 배포하게 됩니다 | "실제 휴대폰 확인은 저작권 점검(3번 프롬프트)을 마치고 올린 뒤에"로 순서를 밝히거나, 이 문장을 '공유하기' 절 뒤로 옮깁니다
- [중] ep12 | "로그인 등 접근 제한 조치" | 바로 아래 발표자 사례의 '입장 코드'를 이 ③의 접근 제한으로 오해할 수 있습니다. 가림막 수준의 입장 코드가 제25조의 접근 제한 조치에 해당한다고 보기는 어렵습니다(확인 필요) | ③ 옆에 "화면의 입장 코드는 여기 해당한다고 보기 어렵습니다. 교과서 자료가 섞이면 학교 학습 플랫폼으로"를 한 줄 넣습니다
- [중] setup | "firebase init hosting을 해 줘" | init과 login은 화살표·Enter로 답하는 대화형 명령입니다. 클로드 코드가 실행하면 질문에 답할 수 없어 멈추거나 기본값으로 넘어갈 수 있습니다. "질문이 나오면 나에게 보여 주고"는 기대대로 되지 않을 가능성이 큽니다(확인 필요). 또 "firebase init hosting은 브라우저 로그인이 필요"라는 말은 틀립니다. 브라우저가 필요한 것은 login입니다. 데스크톱 앱만 설치했을 때 터미널에서 `claude mcp add`, `claude plugin` 명령을 쓸 수 있는지도 확인이 필요합니다 | "firebase login과 firebase init hosting은 선생님이 터미널에서 직접 치고, 위 표대로 답합니다"로 바꿉니다. 아니면 "init 대신 public 폴더를 쓰는 firebase.json과 내 프로젝트 ID를 적은 .firebaserc를 직접 만들어 줘"로 시킵니다. 터미널 절에는 "claude 명령이 없다고 나오면 클로드 코드 대화창의 /plugin 또는 프롬프트로 하세요"를 넣습니다
- [중] ep15 | "방금 고친 것을 모두 되돌리고" | 커밋 전 실수를 되돌릴 때 클로드가 git으로 되돌리면 선생님이 직접 고친 커밋 안 된 내용까지 사라질 수 있습니다. SPEC으로 확인된 /rewind 안내가 아직 없습니다 | '이럴 땐'과 '저장 지점을 안 남겼어요'에 "저장 지점 전이라면 입력창에 /rewind를 치고 되돌릴 시점을 고릅니다(코드만 / 코드와 대화)"를 넣습니다. 함께 "클로드가 명령으로 바꾼 파일(지우기·옮기기)은 되돌려지지 않을 수 있습니다"와 "데스크톱 앱 Code 메뉴에서 같은 이름인지는 확인 필요"를 붙입니다
- [중] setup | "Cowork 플러그인 메뉴 경로는 확인 필요" | SPEC 검증 추가로 경로(설정 › 사용자 지정 › 플러그인, menus 표와 같음)와 "uv로 내 PC에서 도는 로컬 MCP 플러그인은 데스크톱 앱에서만 동작"이 확인됐는데 본문에 없습니다. 한글 플러그인은 바로 그 경우라 웹 Cowork나 claude.ai에서 찾으면 실패합니다 | "설정 › 사용자 지정 › 플러그인(menus 표와 같음)에서 넣습니다. 한글 플러그인은 내 PC에서 도는 방식이라 데스크톱 앱에서만 됩니다. uv 설치는 그대로 필요합니다"로 바꾸고 '확인 필요'를 지웁니다

전체 한 줄 평: 1차 지적은 대부분 반영됐지만, 새로 넣은 ep8 입장 코드 권고가 같은 책의 "교사 이름은 올리지 마"와 부딪치고 정적 파일의 평문 노출을 가볍게 표현합니다. ep8·ep12 프롬프트에 끼워 넣은 Firebase 줄은 편집 표시와 배포 순서 문제를 그대로 안고 있어, 이 두 곳을 먼저 다듬어야 합니다.
