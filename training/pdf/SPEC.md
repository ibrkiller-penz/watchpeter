# 클로드 코드 교사 연수 PDF — 제작 명세 (팀 공용)

## 독자
부산 AI&창의 교사 모임 선생님들. 코딩 완전 초보. 클로드 채팅은 써 봤을 수도 있음. 혼자 PDF만 보고 따라 할 수 있어야 함.

## 구성 원칙: 쇼츠처럼
- 에피소드(EP)마다 첫 장은 **훅**: "이런 일이 됩니다" 한 줄 + 넣는 것 → 나오는 것(전/후) + 걸리는 시간. 3초 만에 이해되게 짧게.
- 그 뒤 본문은 **자세하고 친절하게**: 왜 필요한지 → 준비 → 단계별 따라 하기(각 단계마다 설명) → 복사용 프롬프트 → "왜 이렇게 말하나요?"(프롬프트 줄별 해설) → 화면에서 일어나는 일(예상 대화) → 확인 → 이럴 땐(자주 하는 실수) → 한 줄 정리.
- 말투: 존댓말, 짧은 문장, 쉬운 말. 전문 용어는 처음 나올 때 괄호로 풀이(예: 커밋(저장 지점)). 이모지 금지.
- 프롬프트의 바꿔 쓸 부분은 [대괄호].

## 사실 관계 (지어내지 말 것)
- 클로드 코드 여는 곳: Claude 데스크톱 앱의 Code 메뉴(내 PC 폴더, 업무 처리 추천) / claude.ai/code 웹·휴대폰 앱(클라우드, GitHub 저장소 연결, 앱 만들고 올리기 편함). 유료 요금제(Pro 이상) 필요. 메뉴 이름은 버전에 따라 다를 수 있다고 한 번만 언급.
- 클로드는 명령 실행·파일 수정 전에 허락을 묻는다("실행해도 될까요?"). 읽고 허락.
- 한글 파일은 .hwpx로 저장해 넣으면 다루기 쉽다(.hwp 옛 형식은 어려움).
- 구체적 버튼 위치·단축키를 지어내지 말 것. 확실치 않은 UI는 일반적으로 표현.
- 클로드 답변 예시(화면에서 일어나는 일)는 "예시"임을 밝히고, 그럴듯한 수준으로만.

## 발표자 실제 사례 (저장소 ibrkiller-penz/watchpeter 기록 근거 — 이 범위 안에서만 서술)
- 손목 컨트롤러: Waveshare ESP32-C6 AMOLED 시계가 PC에 블루투스 키보드로 연결. 화면 탭/손목 튕김으로 PPT 넘김(→,←, 마침표=암전), 실행 화면 아이콘 9개(Claude·나이스·유튜브·쿨메신저·카카오톡·한글·탐색기·바탕 화면·창 닫기), 회의 화면(Zoom·Teams·Meet 마이크·카메라·손 들기), 설정. 화면 5개(시계·발표·실행·회의·설정). 버튼 BOOT/PWR.
- 만든 것: 시계 펌웨어, 웹 시뮬레이터(시계 화면·가상 PC·HID(보낸 키) 로그), 브라우저에서 USB로 설치하는 설치 페이지, 초보용 '따라 하기' 안내서(대상: 시계를 산 교사·학생, 쉬운 한국어. 1단계 = 원래 펌웨어 백업), PC 바로 가기 PowerShell 스크립트(wrist-shortcuts.ps1: 관리자 권한 불필요, 못 찾은 앱은 건너뛰고 알림, 다시 실행하면 덮어쓰기), GitHub Pages로 배포, 앱처럼 설치(PWA).
- 일정: 2026-10-17 시뮬레이터 첫 배포 → 10-18 실제 시계로 손목 튕김 녹화(CSV, 바깥 6·안쪽 3 세게 + 약하게 2, 천천히 돌리기) → 튕김 판정 기준 1.0g로 조정, 오작동 걱정에 튕김 기본값 '꺼짐' → 10-18 따라 하기 안내서 → 10-24~26 2호기 고도화 1~5회차(화면 5개, 테마 5종, PWR 짧게=시계+눈 / 두 번=시계 숫자, 실행 타일이 PC 설정 없이 Win+R로 앱 열기). 10일간 커밋 26개.
- 고친 사례: "폰 탭 취소 문제 수정", "설정 화면 닫기 개선", "끊김 배너 축소, 시계 모드에선 숨김", "잠깐 알림 위치 수정".
- 안내서 숫자 = 설정 파일(shared/gesture.json) 값과 같아야 하고, 다르면 자동 검사(guide.test.ts)가 실패하게 만들어 둠. 버튼 동작 바꿀 때 안내서도 같이 갱신("따라 하기: 전원 버튼 설명 갱신").
- 이 연수 자료 자체: 카톡 캡처 한 장 + 세 줄 요청("클로드 코드를 선생님들이 사용할 수 있도록 연수 자료 제작. 선생님들은 초보. 예시 프롬프트와 자료 던지고 업무처리 및 클로드 코드로 앱 개발하는 법. 그리고 개발된 앱 한번 점검하고 수정하는 법.. 내가 한 일들을 예시로.")으로 만들었고, PDF판은 "팀을 짜서"(클로드가 여러 작가 에이전트를 나눠 씀) 만들었음.
- 확인 안 된 것(쓰지 말 것): 설계 문서를 실제로 어떻게 받았는지의 구체 대화, 휴대폰 작업 여부의 세부.

## 출력 형식
- HTML 조각만 출력(<html>/<head>/<style> 금지). 아래 클래스만 사용. 인라인 style 금지.
- 에피소드 하나 = `<section class="ep">` 하나. 각 section은 새 쪽에서 시작(CSS가 처리).

```html
<section class="ep" id="ep3">
  <div class="hook">
    <p class="ep-no">EP 3</p>
    <p class="hook-line">PDF 공문 두 개가 <em>내 할 일 표</em>로</p>   <!-- em = 형광펜 강조 -->
    <div class="io"><div class="in"><b>넣는 것</b>공문 PDF 2개</div><div class="arrow">→</div><div class="out"><b>나오는 것</b>마감일 순 할 일 엑셀</div></div>
    <p class="time">약 3분</p>
  </div>
  <h2>공문·지침 PDF를 할 일 목록으로</h2>
  <p class="intro">왜 필요한지 2~4문장.</p>
  <h3>준비</h3>
  <ul>…</ul>
  <h3>따라 하기</h3>
  <ol class="steps">
    <li><h4>단계 제목</h4><p>설명…</p></li>
  </ol>
  <div class="prompt"><p class="lbl">이렇게 말하세요</p><pre>프롬프트 본문</pre></div>
  <div class="explain"><p class="lbl">왜 이렇게 말하나요?</p>
    <dl><dt>“[중학교 담임]인 내가”</dt><dd>설명</dd> …</dl></div>
  <div class="screen"><p class="lbl">화면에서 일어나는 일 (예시)</p>
    <p class="me">나: …</p><p class="ai">클로드: …</p></div>
  <div class="check"><p class="lbl">확인하세요</p><ul>…</ul></div>
  <div class="oops"><p class="lbl">이럴 땐</p><dl><dt>증상</dt><dd>해결</dd></dl></div>
  <div class="case"><p class="lbl">발표자 사례</p><p>…</p></div>   <!-- 사례 있을 때만 -->
  <p class="takeaway">한 줄 정리 문장</p>
</section>
```
- 표가 필요하면 `<table class="tbl">` (thead/tbody).
- 한 에피소드 분량: A4 2~4쪽(본문 약 1,200~2,200자 + 프롬프트).

# 개정 2판 (업무 위주) — 이 절이 위 내용보다 우선

사용자 요청: "업무 위주로. 시간표 앱 만들기. 성적처리 인정점 프로그램 만들기 중심으로"

## 새 구성
- 1부 업무 처리: EP0~EP5 (part-a.html, 그대로 유지)
- 2부 시간표 앱 만들기: EP6~EP8 (part-b.html, 새로 씀)
- 3부 성적처리 인정점 프로그램: EP9~EP11 (part-d.html, 새로 씀)
- 4부 점검·고치기·지킬 것: EP12~EP13 + 부록 wrap (part-c.html, 새로 씀). 예시 앱은 시간표 앱과 인정점 프로그램. 발표자 손목 컨트롤러 사례는 여기서 압축해 '발표자 사례'로만.
- 이전 원고 old-part-b.html(앱 만들기·손목 컨트롤러·공유), old-part-c.html(점검·수정)은 참고·재사용 가능.

## 공통 원칙 (2·3부)
- 앱은 "HTML 파일 하나, 인터넷 없이 크롬으로 열림". 외부 라이브러리·서버 없음.
- 데이터 입력은 "엑셀에서 표를 복사 → 앱 화면에 붙여 넣기" 방식(파일 업로드·외부 전송 없음). 필요하면 결과도 "복사 → 엑셀에 붙여 넣기" 또는 CSV 저장.
- 만들 때는 **가짜(가명) 데이터**로만 만들고 시험. 실제 성적·실명 파일은 클로드 작업 폴더에 넣지 않는다. 완성된 HTML을 내 PC에서 열어 실제 데이터를 붙여 넣는다(이때 데이터는 내 브라우저 안에서만 처리됨 — 이것이 앱이 그렇게 만들어졌는지 클로드에게 확인받는 프롬프트도 넣을 것).
- 흐름: 계획만 받기 → 가장 작은 판 → 하나씩 키우기 → 검산/점검 → 저장 지점(커밋).

## 시간표 앱 사실 범위
- 일반 예시로 서술(특정 학교 아님). 입력: 학급 시간표(반 × 요일 × 교시 → 과목, 교사). 기능 예: 반별 보기, 교사별 보기(엑셀 표를 교사 기준으로 뒤집기), 오늘 내 수업, 특정 요일·교시에 수업 없는 교사 찾기(보강·교체 후보), 교체 반영 후 두 교사 시간표 겹침 검사. 교실 TV·휴대폰에서 보기.
- 시간표에는 교사 이름이 들어가므로 공개 GitHub Pages에 올리지 말고 학교 안에서 파일로(쿨메신저·메일 등) 나눈다고 안내.
- 실제 학교 시간표 프로그램 이름이나 나이스 시간표 메뉴를 지어내지 말 것.

## 인정점 프로그램 사실 범위 (매우 중요)
- 인정점: 정당한 사유로 정기고사(지필평가)를 보지 못한 학생에게 규정에 따라 인정해 주는 점수. **계산 방법·비율은 시·도교육청 지침과 각 학교 학업성적관리규정에 따라 다르다.** 특정 공식을 정답처럼 쓰지 말 것.
- 예시 공식은 반드시 "예시(우리 학교 규정이 이렇다고 가정)"로 표시. 예: 결시 사유별 인정 비율(예: 출석인정 결시 100%, 질병 결시 80% 등 — 예시), 같은 과목 다른 고사 점수의 비율을 결시 고사 만점에 환산. 반올림 자리, 다른 고사도 결시한 경우 등 예외 처리는 규정을 따른다.
- 핵심 메시지: ① 규정 문서(PDF·hwpx)를 클로드에게 주고 **계산 규칙을 표로 정리받아 사람이 확정**(코드보다 먼저) ② 그 표대로 프로그램 ③ **손으로 계산한 예시 5~10건과 자동 비교(검산)**, 경계 사례(만점이 다른 고사, 두 고사 모두 결시, 소수점 반올림, 점수 0점) ④ 결과는 담당자가 확인하고, 학업성적관리위원회 심의 등 학교 절차와 나이스 입력은 기존대로(프로그램은 계산·검산 보조).
- 성적은 민감한 개인정보: 실명·실제 점수를 클로드에 넣지 않는다. 가짜 학생01~학생20 데이터로 만들고 검산.
