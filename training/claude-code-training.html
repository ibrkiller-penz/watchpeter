클로드 코드로 업무 처리하고 앱 만들기

코딩을 몰라도 됩니다. 자료를 넣고, 아래 프롬프트를 복사해 내 상황에 맞게 몇 단어만 바꾸면 됩니다. 예시는 모두 발표자가 실제로 한 일입니다.

대상 코딩 초보 교사소요 읽기 20분 + 실습 30분쓰는 법 노란 복사 버튼 → 붙여 넣기 → [ ] 부분만 고치기

0시작 전 10분

클로드 코드가 무엇이고, 어디서 열고, 어떻게 말하면 되는지.

채팅 클로드와 무엇이 다른가

클로드 채팅클로드 코드
하는 일답을 글로 알려 줌내 폴더 안에서 파일을 직접 만들고, 고치고, 실행함
결과물복사해서 내가 붙여 넣어야 함완성된 파일(.hwpx, .xlsx, .html 등)이 폴더에 생김
잘 맞는 일아이디어, 문장 다듬기파일 여러 개 정리, 반복 작업, 앱·웹페이지 만들기

어디서 여나

  • Claude 데스크톱 앱의 Code 메뉴 — 내 컴퓨터 폴더를 골라 바로 작업. 업무 처리(한글·엑셀 파일)에 추천.
  • claude.ai/code (웹·휴대폰 앱) — 설치 없이 클라우드에서 작업. GitHub 저장소와 연결해 앱을 만들고 올릴 때 편함. 발표자는 휴대폰에서도 이렇게 작업했습니다.
  • 유료 요금제(Pro 이상)가 필요합니다. 메뉴 이름은 버전에 따라 조금 다를 수 있습니다.

첫 준비: 작업 폴더 하나

  1. 바탕 화면에 클로드작업 폴더를 만들고, 그 안에 일마다 하위 폴더를 만듭니다(예: 가정통신문_11월).
  2. 쓸 자료(양식, 엑셀, PDF, 캡처 사진)를 복사본으로 넣습니다. 원본은 따로 둡니다.
  3. 클로드 코드에서 그 폴더를 열고 말을 겁니다. 클로드는 이 폴더 안만 봅니다.
  4. 클로드가 "이 명령을 실행해도 될까요?" 하고 물으면 읽어 보고 허락합니다. 파일을 지우는 명령이면 한 번 더 확인합니다.

프롬프트 공식: 다섯 칸

한 줄로 던져도 되지만, 아래 다섯 칸을 채우면 다시 시킬 일이 줄어듭니다.

누구에게학부모, 2학년 학생, 교감 선생님
무엇을가정통신문, 명단 정리, 퀴즈 앱
어떤 자료로폴더 안 파일 이름을 그대로
어떤 모양으로A4 한 장, 엑셀 표, 휴대폰 화면
어떻게 확인"끝나면 요약하고 이상한 점 알려 줘"

마지막에 "모르는 게 있으면 시작 전에 질문해 줘"를 붙이면, 클로드가 짐작으로 채우지 않고 먼저 묻습니다.

1업무 처리: 자료 던지고 맡기기

자료는 폴더에 넣고, 프롬프트에는 파일 이름을 적습니다. [ ] 안만 바꿔 쓰세요.

가정통신문 초안 만들기

한글 .hwpx
넣을 자료
학교 가정통신문 양식(.hwpx), 행사 메모(메모장이나 카톡 내용 복사)
팁
한글에서 다른 이름으로 저장 → .hwpx로 바꿔 넣으면 다루기 쉽습니다(.hwp 옛 형식은 어려움).
PROMPT
폴더의 [가정통신문양식.hwpx]를 양식으로 써서 [11월 학부모 공개수업] 가정통신문을 만들어 줘.
내용은 [메모.txt]에 있어.
- 읽는 사람: 학부모. 쉬운 말, 존댓말, A4 한 장.
- 날짜·시간·장소는 메모에 있는 그대로만 쓰고, 없으면 [  ]로 비워 둬.
- 결과는 새 파일 [가정통신문_공개수업.hwpx]로 저장. 양식 원본은 건드리지 마.
끝나면 내가 꼭 확인해야 할 부분(날짜, 숫자, 담당자)을 목록으로 알려 줘.

확인 날짜·요일이 맞는지, 메모에 없는 내용을 지어내지 않았는지 사람이 직접 봅니다.

엑셀 여러 개 합치고 이상한 값 찾기

엑셀 .xlsx
넣을 자료
반별로 받은 신청서 엑셀 여러 개(가명 처리본)
PROMPT
폴더에 반별 [방과후 신청] 엑셀이 [7]개 있어. 하나의 표로 합쳐 줘.
- 열: 반, 번호, 이름, 신청 강좌, 비고
- 같은 학생이 두 번 들어간 줄, 빈칸, 강좌 이름이 목록과 다른 줄은 노란색으로 표시하고 '확인필요' 시트에 따로 모아 줘.
- 강좌별 신청 인원 합계 시트도 만들어 줘.
- 결과는 [방과후_통합.xlsx]. 원래 파일은 고치지 마.
몇 줄을 합쳤고 몇 줄이 '확인필요'인지 숫자로 알려 줘.

확인 클로드가 말한 합계와 원본 파일 줄 수 합이 맞는지 한 번 세어 봅니다.

긴 공문·지침 PDF → 내가 할 일 목록

PDF
넣을 자료
교육청 공문, 지침 PDF(여러 개도 됨)
PROMPT
폴더의 PDF [2개]를 읽고 [중학교 담임]인 내가 해야 할 일만 뽑아 줘.
- 표로: 할 일 / 마감일 / 제출 방법 / 근거 쪽수
- 마감일이 빠른 순서로.
- 나와 상관없는 내용(관리자, 다른 학교급)은 빼고, 애매한 건 '확인필요'로 따로 적어.
- [할일_정리.xlsx]로 저장하고, 화면에는 이번 주 할 일 3개만 짧게.

확인 '근거 쪽수'를 열어 원문과 맞는지 한두 개만 확인해도 믿을 만한지 알 수 있습니다.

상장·수료증 수십 장 한 번에

한글 + 엑셀
넣을 자료
상장 양식(.hwpx) 하나, 명단 엑셀(이름·상 이름·날짜)
PROMPT
[상장양식.hwpx]와 [수상자명단.xlsx]로 상장을 만들어 줘.
- 명단 한 줄 = 상장 한 장. 이름, 상 이름, 날짜를 양식의 같은 자리에 넣어.
- 한 파일에 모아 [상장_모음.hwpx]로, 한 장씩 쪽 나눔.
- 먼저 첫 두 명만 만들어 보여 주고, 내가 괜찮다고 하면 나머지를 만들어.

요령 "먼저 두 개만 → 확인 → 나머지" 순서는 모든 대량 작업에 씁니다. 틀리면 두 장만 고치면 됩니다.

2앱 만들기: 작게 만들고 키우기

발표자가 만든 '손목 컨트롤러'의 흐름을 그대로 따라 하면 됩니다. 코드는 한 줄도 직접 쓰지 않았습니다.

무엇을 만들었나: 손목 컨트롤러

손목시계(ESP32 AMOLED 시계)가 PC에 블루투스 키보드로 붙어서, 화면을 누르거나 손목을 튕기면 PPT를 넘기고, 나이스·한글·카톡을 열고, 화상 회의 마이크를 끕니다. 수업 중 교탁으로 돌아가지 않으려고 만들었습니다. 시계 펌웨어, 웹 시뮬레이터, 설치 페이지, 초보용 안내서까지 모두 클로드 코드로 만들었습니다.

실제로 한 순서 (2026년 10월)

  1. 시작아이디어를 한 문단으로"수업 중 손목으로 PPT 넘기기, 앱 열기, 회의 마이크 끄기." 무엇을, 누가, 어디서 쓰는지만 적었습니다.
  2. 설계코드보다 계획 문서 먼저"아직 만들지 말고 계획만" 이라고 해서 화면 배치·버튼 동작·설치 방법을 문서로 먼저 받았습니다. 이후 모든 수정은 이 문서를 기준으로 했습니다.
  3. 10.17진짜 기계 전에 시뮬레이터시계가 없어도 웹에서 시계 화면·가상 PC·보낸 키 기록을 볼 수 있게 먼저 만들어 올렸습니다. 고칠 때마다 휴대폰으로 바로 눌러 봤습니다.
  4. 10.18실제 기기 데이터로 맞추기손목 튕김을 실제 시계로 녹화(CSV)해서 클로드에게 주고, 어느 세기부터 '넘김'으로 볼지(1.0g)를 데이터로 정했습니다. 오작동이 걱정돼 기본값은 '꺼짐'으로 바꿨습니다.
  5. 10.18쓰는 사람용 안내서"시계를 산 교사·학생(코딩 초보) 대상, 쉬운 한국어" 조건으로 '따라 하기' 안내서를 만들었습니다. 1단계는 원래 펌웨어 백업입니다.
  6. 10.24–262호기, 고도화 5회차써 보면서 불편한 점을 모아 회차별로 고쳤습니다. 화면 5개, 테마 5종, 버튼 두 번 누르기, PC 설정 없이 바로 여는 실행 타일.

10일 동안 저장 지점(커밋) 26개. 한 번에 크게 만들지 않고, 보이는 것 하나 → 써 보기 → 고치기를 반복했습니다.

3만든 앱 점검하고 고치기

만드는 것보다 고치는 일이 더 깁니다. 순서만 지키면 어렵지 않습니다.

점검 순서 네 가지

  1. 내가 직접 써 보고 적기. 이상한 점을 그때그때 메모합니다. 화면 캡처가 가장 좋은 설명입니다.
  2. 클로드에게 점검 맡기기. "초보 사용자 입장에서", "휴대폰 화면에서", "잘못 눌렀을 때" 처럼 관점을 정해 줍니다.
  3. 한 번에 하나만 고치기. 고치기 전에 원인을 먼저 설명하게 하고, 고친 뒤 무엇을 눌러 확인할지 받습니다.
  4. 저장 지점 남기기. 잘 될 때마다 "여기까지 저장해 줘(커밋)". 망가지면 이 지점으로 되돌립니다.

발표자 사례 시뮬레이터에서 "휴대폰으로 탭하면 취소되는 문제", "설정 화면이 잘 안 닫히는 문제"를 이 방식으로 하나씩 고쳤습니다.

설명서와 앱이 어긋나지 않게

배운 점
버튼 동작을 바꿀 때마다 "안내서도 같이 고쳐 줘"를 붙였습니다. 커밋 기록에 '따라 하기: 전원 버튼 설명 갱신'처럼 남아 있습니다.

방금 바꾼 내용에 맞춰 사용 안내 페이지도 같이 고쳐 줘.

되돌리기 전에 어느 지점으로 가는지, 무엇이 사라지는지 먼저 알려 줘.

같은 문제가 두 번 안 풀리면

  • 같은 말을 반복하지 말고 캡처, 정확한 순서, 기기 이름을 더 줍니다.
  • "지금까지 시도한 것과 결과를 정리해 줘" → 그 요약을 들고 새 대화에서 다시 시작합니다. 대화가 길어지면 앞 내용을 놓치기 쉽습니다.
  • "원인 후보를 3개 들고, 각각 어떻게 확인할 수 있는지부터 말해 줘."

2호기 고도화는 이렇게 했습니다

일주일 써 보며 불편한 점을 메모 → 비슷한 것끼리 묶어 회차(1~5회차)로 나눔 → 회차마다 "이번엔 이것만" 지시 → 시뮬레이터로 확인 → 저장. 한 회차에 고칠 것은 3~5개 이내로 두었습니다.

학생 개인정보

  • 실명·연락처·성적·건강 정보는 넣지 않습니다. 필요하면 가명(학생01, 학생02)으로 바꾼 복사본을 씁니다.
  • 공개 GitHub에 올리는 앱과 자료에는 학생 정보가 없어야 합니다. 올리기 전에 "개인정보가 들어 있는지 검사해 줘".
  • 학교·교육청의 생성형 AI 사용 지침을 먼저 확인합니다.

원본은 따로, 결과는 사람이 확인

  • 원본은 건드리지 않게 "원래 파일은 고치지 마, 새 파일로 저장해"를 붙입니다. 발표자의 시계 안내서도 1단계가 원래 상태 백업입니다.
  • 날짜·숫자·이름·금액은 마지막에 사람이 확인합니다. 클로드는 그럴듯하게 틀릴 수 있습니다.
  • "실행해도 될까요?"를 무조건 허락하지 않습니다. 지우기·보내기·올리기는 특히 읽어 봅니다.
